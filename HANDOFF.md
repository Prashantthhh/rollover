# RollOver Warangal: handoff

A static site: Next.js 15 (App Router, `output: "export"`), Tailwind CSS 4, the `motion` package for animation.
`npm run build` writes plain HTML/CSS/JS to `out/`, which any static host can serve. It is set up for Vercel.

## Before launch

Every `[CONFIRM` marker on the page must be gone before the real domain goes live. `scripts/check-confirm.mjs` (run by `npm run build`)
only warns until you set the environment variable `LAUNCH_CHECK=1` in Vercel (Project Settings > Environment Variables). With it set, the build
fails while any marker is left, so set it on launch day and fix whatever it lists. Run `npm run build` to see the current list.

| Marker on the page | Where it shows | What to confirm | How to clear it |
|---|---|---|---|
| `[CONFIRM] hours` | Visit section, footer | Opening hours (now Mon-Fri 11 AM to 11 PM, Sat-Sun 10 AM to 11 PM, copied from the old site) | Fix `hours` in `src/data/site.ts`, then set `HOURS_CONFIRMED = true` (same file). This also adds the opening hours to the structured data and the "open now" status |
| `[CONFIRM]` rating and review count | Standfirst stats, reviews section | 4.2 stars and 1,300+ reviews (read off Google Maps on 27 Oct 2026) | Re-check on Google Maps, update `rating` in `src/data/site.ts`, then set `RATING_CONFIRMED = true` (same file) |
| `[CONFIRM IF ACTIVE]` | Footer, next to "Partner with us" | Whether the partner / ambassador programme still runs, and the WhatsApp link | Fix `partner.href` in `src/data/site.ts` and set `partner.active = true`; or remove the link from `src/components/Footer.tsx` |
| `[CONFIRM which item]` | Menu header, "Doodle slot 2" placeholder | Which item is the bestseller (the doodle arrow points at it) | Pass the traced doodle `paths` to `<HandDrawn slot={2}>` in `src/components/MenuSection.tsx` (the placeholder, and its marker, disappear), or delete the slot |

The other doodle placeholders (slots 1 and 3, and the empty pull-quote slot in Reviews) carry no `[CONFIRM` text, so they do not block the build, but
they are visible to visitors: fill them (`<HandDrawn paths=...>`, `src/data/reviews.ts`) or remove them before launch too.

## 1. Run it

```powershell
npm install
npm run dev        # http://localhost:3000, live reload
npm run build      # production build into out/ (also runs scripts/postbuild.mjs)
npm start          # serve out/ locally (npx serve out)
npm run check      # SEO checks + structured-data validation (run after a build)
```

Node 20 or newer.

## 2. Where everything lives

| What | File |
|---|---|
| Business facts (name, phone, address, hours, rating, links, map, partner link) | `src/data/site.ts` |
| Menu (all categories, items, prices, veg tags, photos) | `src/data/menu.json` |
| Which items appear in "Specials" and in the photo strip | `src/data/featured.ts` |
| "How rolls are made" step text | `src/data/steps.ts` |
| Reviews (empty = review cards hidden) | `src/data/reviews.ts` |
| Spin-the-wheel prizes and its on/off switch | `src/data/offers.ts` |
| Page title, description, share image, canonical | `src/lib/seo.ts` |
| Structured data (Google "local business" markup) | `src/lib/jsonld.ts` |
| Colours, fonts, shared styles, animation CSS | `src/app/globals.css` |
| Page order | `src/app/page.tsx` |
| Cache headers, old-URL redirects | `vercel.json` |
| What we still need from the cafe | `NEEDS_FROM_CLIENT.md` |

Raw photos and video live in `source-assets/` (never deployed). What the site serves comes from `public/`
(generated by `scripts/optimize-media.mjs`).

## Art direction and slots for hand-made assets

Retro Indian ice cream parlour: three flat colours (pink `#eb3592`, cream `#fef2f3`, maroon `#340a1b`), Shrikhand for big display type,
Archivo for body text, hard offset shadows, square blocks mixed with arches and pills. Colours and fonts are in `src/app/globals.css`
and `src/app/layout.tsx` (swap Archivo for Atkinson Hyperlegible there if wanted). The hero and the menu board are redesigned; the other sections
still carry the older layouts in the new colours.

Slots for hand-made assets live in `src/data/art.ts`: drop a file in `public/art/` and put its path in the file.
`heroLettering` (hand-lettered headline SVG), `doodles.heroTop / heroArch / menuBoard` (doodle SVGs). Until set, a dashed placeholder shows
(`SHOW_SLOT_HINTS`; set it to `false` before launch). New photos and hero footage: see section 4.

**Hero video treatment.** `HERO_TREATMENT` in `src/data/art.ts` picks `"duotone"` (pink + maroon), `"halftone"` (dot screen) or `"none"`.
The look is baked into the files, so the browser does no extra work: `node scripts/bake-clips.mjs` cuts the photo-band video, the three step loops and the strip frames from the same footage. `node scripts/bake-hero.mjs` regenerates
`public/video/hero-duotone.mp4`, `hero-halftone.mp4` and their posters from `source-assets/video/background.mp4`
(needs ffmpeg). When new footage arrives, point `SRC` and the three `trim` cuts in that script at it and re-run.
Only the duotone files are kept in `public/video/`; re-run the script to bring the halftone back. The full-width video band between the menu and the vibe section is `BAND_VIDEO` in the same file.

## 3. The switches (read these first)

| Switch | File | Now | What it does |
|---|---|---|---|
| `HOURS_CONFIRMED` | `src/data/site.ts` | `false` | While false: no "Open now" chip, "Hours may vary" under the hours, no opening hours in the Google markup. Set `true` after the cafe confirms the hours. |
| `OFFERS_CONFIRMED` | `src/data/offers.ts` | `false` | While false: the "Feeling lucky?" banner and the spin-the-wheel are not rendered at all. Set `true` once the prizes and the staff check are agreed. |
| `partner.active` | `src/data/site.ts` | `false` | While false the footer "Partner with us" link carries a visible `[CONFIRM IF ACTIVE]` tag. |
| `NEXT_PUBLIC_GA_ID` | Vercel environment variable | unset | Google Analytics 4 loads only when this is set (for example `G-ABC123XYZ`). Redeploy after setting it. |

## 4. Everyday edits

**Change a price, name or description.** Open `src/data/menu.json`, find the item (search for its name) and edit
`price` (a number in rupees, no symbol), `name`, `desc`. Save, rebuild.

**Change veg / non-veg.** The `veg` field on the item: `true` or `false`.

**Add a menu item.** Copy an existing item inside its category's `items` list and edit it. For a photo see "Replace or add a photo" below.

**Add or remove a category.** Add an object to `categories` (`id`, `title`, `hidden: false`, `items: []`). Tabs appear in the
order of the file. To hide one without deleting it, set `"hidden": true` (Beverages is hidden until it has real photos and descriptions).

**Item with no photo yet.** Set `"image": null`. The card shows a pink "Photo coming soon" tile.

**Specials on the home page and the photo strip.** `src/data/featured.ts`: two lists of `findItem("category-id", "Exact item name")`.
The build fails with a clear message if a name does not match `menu.json`.

**Hours.** `site.hours` in `src/data/site.ts` (24-hour `"11:00"`). The Visit section, footer and Google markup all read from it.
Then set `HOURS_CONFIRMED = true`.

**Rating.** `site.rating` in `src/data/site.ts`: `value` and `label`. It feeds the hero sticker, the reviews section and the chips.
Check it against the Google listing (last checked 27 Oct 2026: 4.2, 1,300+ reviews). It is deliberately **not** put into the Google markup
(Google does not allow self-published ratings for local businesses).

**Reviews.** Add real ones to `src/data/reviews.ts` (name, their words, optional `rating` 1–5, optional `when`). Never invent or paste from elsewhere.

**Phone, address, social, Swiggy/Zomato links, map.** `src/data/site.ts`.

**Spin-the-wheel prizes.** `src/data/offers.ts`: `prizes` (label lines, title, `minOrder`), `LOCK_HOURS`. A win shows a random code such as RO-4F7K with the date and time.
That code is made on the visitor's phone and cannot be verified by the site; see `NEEDS_FROM_CLIENT.md`.

**Page title, description, share image.** `src/lib/seo.ts` (keep the title under 60 and the description under 155 characters; `npm run check` tests this).

**Replace or add a photo.**
1. Put the original in `source-assets/menu/` (or `vibe/`, `cutouts/`, `brand/`), named like `waffle-cones-mango.jpg`.
2. `node scripts/optimize-media.mjs` writes `public/img/<folder>/<name>.webp` and a smaller `-sm.webp`.
3. Point the item's `image` at `/img/menu/<name>.webp` (without `-sm`). Always run the script: the site expects both files.

**Replace the hero video.** Encode a short loop (keep it under 1 MB, no audio) and a poster:
```powershell
ffmpeg -i new.mp4 -vf scale=1280:720,fps=24 -c:v libx264 -crf 27 -preset slow -pix_fmt yuv420p -movflags +faststart -an public/video/hero.mp4
ffmpeg -ss 0.3 -i public/video/hero.mp4 -frames:v 1 hero-poster.png   # then save as public/video/hero-poster.webp (1280 px wide)
```
Then re-run `node scripts/optimize-media.mjs` (it also makes `hero-poster-sm.webp`).

**Vibe section photos and captions.** `tiles` at the top of `src/components/VibeSection.tsx`.

**Share image (1200x630) and icons.** Share image: edit `scripts/og-image.html`, open it at 1200x630 in a browser (replace `FONT` with the Fredoka file in `out/_next/static/media/*.p.woff2`) and save as `public/og-image.png`.
Icons: `npm run icons` redraws `src/app/icon.png`, `apple-icon.png`, `favicon.ico` and `public/icons/*`.

## 5. Checks before launch

```powershell
npm run build
npm run check                 # title/description lengths, canonical, Open Graph, sitemap, robots, structured data
```
`npm run check` includes `scripts/validate-jsonld.mjs`, which checks the structured data against the official schema.org vocabulary.
After deploying, also run the live URL through Google's Rich Results Test and Search Console.
Accessibility: `node scripts/audit-a11y.mjs` (needs `npm i --no-save playwright`, plus `npx serve out` running). It runs axe, a contrast check and a keyboard walkthrough.

## 6. Deploy on Vercel

First time (creates the project and a preview URL):
```powershell
npx vercel login
npx vercel                 # preview deployment; answer: link to a new project "rollover-warangal", directory ./
```
Preview URLs are behind Vercel login by default. To test headers with curl, turn off Deployment Protection for previews in the project settings, or use a bypass token.

Production:
```powershell
npx vercel --prod
```
or connect the Git repository in the Vercel dashboard and every push to `main` deploys.

Settings to check in Vercel: Framework Preset "Next.js"; build command `npm run build`; no output directory override (the static export is detected). Add `NEXT_PUBLIC_GA_ID` under Environment Variables when you have it.

**Domain.** Project > Settings > Domains > add `rolloverwarangal.com` (and `www`, redirecting to the apex or the reverse). Vercel shows the exact DNS records to set at the registrar.
The old site's URLs (`/Comp`, `/Events`, `/offers` ...) 301-redirect to the matching section of the home page (see `redirects` in `vercel.json`). Matching is by exact path as the old site wrote it.

**Headers (in `vercel.json`).** `/_next/static/*`: 1 year, immutable (file names are hashed). `/img/*`, `/video/*`, `/icon.png`: 30 days + stale-while-revalidate (file names are not hashed,
so after replacing a photo with the same name, visitors may see the old one for up to 30 days; give changed photos a new name to avoid that).
Check on the live URL:
```powershell
curl.exe -sI https://<url>/video/hero.mp4 | findstr /i "cache-control x-content-type-options"
```

## 7. Things to know

- Below-the-fold sections use `content-visibility: auto` for speed. In-page links and the first Tab key press switch it off so jumps and focus land exactly (`src/components/HashNav.tsx`).
- The hero scroll effect is driven by one CSS variable (`--p`) set in `src/components/HeroScrub.tsx`; the layout rules are in the "Hero" block of `globals.css`.
- Animation honours `prefers-reduced-motion` everywhere: no pinning, no scroll effects, no drifting shapes, the video stays on its poster. It also stays on the poster with Data Saver or a 2G connection.
- `scripts/build-menu-json.mjs` was a one-off import from the old site. **Do not run it again**: it overwrites `menu.json`.
- `scripts/postbuild.mjs` adds a font preload after the build and writes the exact canonical URL. It runs as part of `npm run build`.
- Images use a custom loader (`src/lib/imageLoader.ts`) because a static export has no image server. That is why every image needs its `-sm.webp` twin.
- Three old-site photos with other accounts' watermarks were removed (see `NEEDS_FROM_CLIENT.md`). Do not re-add them.
- `reference/` (motion study of another site) and `old-site/` (recovered code and data) are not part of the build and are not deployed.
